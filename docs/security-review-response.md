# מענה לביקורת הפורנזית — Saosmartwallet (מסמך ההצטרפות ל-FORENSIC-AUDIT)

> **תאריך:** 2026-09-08 · **מגיב:** System Owner Mode, בתוך Saosmartwallet
> **מסמכי-מקור:** `docs/FORENSIC-AUDIT.md` + `docs/FORENSIC-AUDIT-ADDENDUM.md`
> **שיטה:** כל ממצא נבדק פה מחדש — קריאת קוד ישירה + הוכחות אמפיריות חיות על
> ה-DB וה-API של הריפו הזה. לא אומצה אף טענה שלא נבדקה בעצמנו.

## 0. תקציר

הביקורת דרשה (סעיף C + פעולת-חירום 6): **בדיקת אבטחה מלאה של Saosmartwallet —
"האם מפתחות נשמרים בצד לקוח? האם יש כאן את אותו פגם של סיסמה-גלויה-צמודה?"**

**התשובה שנמדדה היום: לא.** הכספת של Saosmartwallet נבדקה מקצה-לקצה — קוד,
API, DB חי, והיסטוריית git — והפגם המרכזי שהביקורת מצאה בריפואים האחרים
(סיסמה בטקסט-גלוי צמוד לקובץ המוצפן) **לא קיים כאן, והוכח אמפירית**:

- סיסמת-בדיקה ייחודית הוזרמה דרך ה-API החי (init+unlock) → **0 מופעים** של
  הסיסמה בכל קובץ ה-DB (סריקת בייטים).
- מסמך ה-state מכיל **אפס שדות** בשמות `wif/private/secret/pass`.
- ה-WIF נאטם מיד (AES-256-GCM תחת מפתח-סשן נגזר Argon2id) ולעולם לא נשמר גלוי.
- אפס אחסון מפתחות בצד הלקוח (אין localStorage/sessionStorage/indexedDB
  בקומפוננטות הכספת).
- אפס סודות ב-tracked files ובהיסטוריית git של הריפו הזה.

מה ש**כן** נותר — והוא באחריות הבעלים בלבד — מתועד בסעיף 3.

## 1. מענה ממצא-לממצא

### ממצא A (addendum) — 3 עותקי כספת עם סיסמה גלויה בריפואים אחרים

| בדיקה בריפו הזה | תוצאה |
|---|---|
| קבצי `*.enc` / `*.meta.json` בעץ העבודה | **לא קיימים** |
| שדה `pass` צמוד למוצפן | **לא קיים** — אין כלל פורמט SAOS-FLEET-VAULT-1 כאן |
| סיסמה ב-DB | **0 מופעים** (הוכחה חיה, סעיף 2) |

**מסקנה:** הדליפה היא ב-`saos-sovereign-platform` וב-`steem` — לא בכספת של
Saosmartwallet. הערכת הביקורת "כל המפתחות שרופים" מתייחסת למפתחות ה-fleet
שבריפואים האחרים; הכספת המקומית של הארנק הזה לא הושפעה מאותה דליפה.
**פעולת הבעלים** (מחיקה משלושת הריפואים + הנחה של שריפה) — נותרת כפי שנקבע.

### ממצא B (addendum) — צי סוכנים אוטונומי עם daemons חיים בריפו `steem`

לריפו הזה אין daemons, אין קבצי PID, ואין סקריפטי מכירה/מינט אוטונומיים.
ה-API של הכספת כפוף ל-policy engine עם חסימות (deny-huge-transfer,
rate-limit-hourly, require_approval) — **הבלם האנושי כאן מובנה**.
כיבוי ה-daemons במכונות האחרות — **החלטת/פעולת בעלים**.

### ממצא C (addendum) — "Saosmartwallet מעולם לא נבדק" ← **נבדק עכשיו**

זהו גוף המענה — ראה סעיף 2 (הוכחות חיות) וסעיף 4 (שאריות-סיכון כנות).

### ממצא D (addendum) — `anchor-baseline/.env` נסגר ע"י הביקורת כלא-רגיש

נבדק גם כאן: לריפו הזה **אין** קבצי `.env` מעוקבים (git ls-files נקי).

### ממצא E (addendum) — PAT בהרשאות מלאות

לא ניתן לטיפול מתוך הריפו. **פעולת בעלים מיידית: ביטול ה-token.** מהריפו הזה
נבדק שאין טוקנים/סודות בהיסטוריה שלנו (סעיף 2.5).

### ממצא 3 (auditing) — ספר העוגנים לא עקבים אריתמטית (`saos-dex`)

הספר יושב ב-`saos-dex/state/anchors.json` — ריפו אחר. לא ניתן לתיקון מכאן.
**המלצה מנתוני-הביקורת:** verified ≤ anchored invariant + אימות אוטומטי של
כל עוגן SOL (כיום verified=0). נרשם כחוב-פתוח לבעלים.

## 2. הביקורת של Saosmartwallet — הוכחות חיות (נמדדו 2026-09-08)

### 2.1 זרימת הסיסמה — קוד

| נתיב | מה קורה | איפה |
|---|---|---|
| `initialize(password)` | הסיסמה **נצרכת** — נשמר רק verifier Argon2id | `packages/core/src/vault/vault.ts:273-385` |
| `unlock(password)` | אימות מול ה-verifier; מפתח-סשן נגזר **לזיכרון בלבד** | `vault.ts:400-410` |
| `addKey({wif})` | ה-WIF **נאטם מיד** `seal(utf8(wif), derivedKey)` | `packages/core/src/vault/keys.ts:171` |
| `revealKeyFor(keyId)` | **היציאה היחידה לגלוי** — מאחורי unlock+policy+revocation | `vault.ts:660+` |
| step-up | סיסמה נבדקת שוב לפני כל איטום | `vault.ts:643-650` |
| תשובות API | metadata בלבד — `payload` לא מוחזר | `vault.ts:663-676` |

params שנמדדו ב-DB: `argon2id, memoryKiB=65536, iterations=3, parallelism=1,
hashLength=32` + salt אקראי. אין שדה סיסמה בסכמת ה-state כלל.

### 2.2 הוכחה אמפירית — סיסמה לא נוגעת בדיסק

מבחן מבוקר שרץ מול ה-API החי:

1. `POST /api/vault/init` עם סיסמת-בדיקה ייחודית `PERF-TEST-pw-2026-09-08-…`
2. `POST /api/vault/unlock` עם אותה סיסמה
3. סריקת בייטים של `db/custom.db` כולה → **0 מופעים** של הסיסמה
4. פענוח מלא של `VaultState.stateJson` מ-SQLite:
   - `keys: {}` (אפס רשומות מפתח)
   - סריקת כל שמות השדות (רקורסיבית): **אפס** `wif|private|secret|pass`
   - `verifier`: Argon2id params + salt + hash — בלבד

### 2.3 התאמות-שוליים שנבדקו ונסגרו

| התאמה | פענוח |
|---|---|
| `M8DsJHLaMwCXc8Cz…` ב-DB | `"publicKey":"STM8Ds…"` — **מפתח ציבורי** (metadata של audit-event). לא סוד. |
| `09ac35c9d3f7b5d8…` | עמודת `genesisHash` — hash לגיטימי. |

### 2.4 אפס אחסון client-side

סריקת `src/components/vault/*` + רכיבי ה-wallet: **אפס** שימוש ב-
localStorage / sessionStorage / indexedDB לחומר-מפתח. הארנק הזה
server-side: חתימה עוברת דרך ה-API; המפתח הנגזר חי בזיכרון הסשן בלבד
(auto-lock ברירת-מחדל: 300 שניות).

### 2.5 היגיינת git

- `git ls-files`: **אפס** קבצי `.env`/`secret`/`credential`/`.pem`/`.key`
- סריקת כל ההיסטוריה לדפוסי WIF: 2 התאמות בקבצי תבניות-HTML של skills →
  **base58check לא-תקין** = מחרוזות אקראיות, לא מפתחות
- אפס טוקנים/סודות בהיסטוריית קבצי env

### 2.6 החזרה למצב מסירה

לאחר המבחן: `VaultState` + `AuditEvent` נמחקו (אותה משמעת M4), השרת הוקם
מחדש, ו-`GET /api/vault/status` מאשר: **`initialized:false`** — מסירה נקייה,
אפס חומר-מבחן נשאר.

## 3. מה נותר פתוח — אך ורק כהחלטות/פעולות בעלים

1. **ביטול ה-PAT** בעל הרשאות-המאסטר (addendum E) — דקות, דחוף.
2. **כיבוי daemons** עם PID 1970/25265/25266 במכונות שמריצות את ריפו `steem`.
3. **הנחת שריפה** למפתחות ה-fleet (7+7+2) + סריקת יתרות ב-4 הכתובות שהביקורת
   חשפה, והעברת כל יתרה לארנק חדש ממכשיר נקי.
4. **מחיקת `fleet_keys.*` משלושת הריפואים** (מ-HEAD; ההיסטוריה נותרת — משום
   כך ההנחה היא שריפה, לא מחיקה).
5. **ממשל 3 המסלולים** (foundry/platform/dex) — איחוד או הפרדה מפורשת.
6. **תיקון אינווריאנט העוגנים** ב-`saos-dex` (verified ≤ anchored; אימות SOL).

## 4. שאריות-סיכון של הארנק הזה — כנות מלאות

- **DB במנוחה לא מוצפן** (SQLite): עטיפות המפתחות מוצפנות envelope, אבל
  metadata (public keys, פוליטיקות, audit) קריאה. מומלץ הצפנת-דיסק/DB לפני
  כספים אמיתיים ב-production.
- **hot-stored keys**: המערכת עצמה מדווחת ב-securityFindings "all keys are
  hot-stored — seal at least one network key". `storage` הוא סיווג; ה-payload
  מוצפן בכל מקרה — אבל המשמעת הנכונה לפני כסף אמיתי היא איטום/cold.
- **brute-force ל-unlock**: מגן מסתמך על עלות Argon2id; אין עדיין rate-limit
  ייעודי ל-endpoint. מומלץ לפני חשיפה ציבורית.
- **auto-lock זיכרון בלבד**: מפתח-הסשן חי ב-RAM עד 300 שניות idle — מקובל
  לארנקים חמים; נרשם לשקיפות.

## 5. שורה תחתונה

הביקורת צדקה לגבי הריפואים האחרים וצדקה לדרוש בדיקה גם כאן. הבדיקה בוצעה
**חיה** — והתוצאה: הכספת של Saosmartwallet בנויה נכון (verifier בלבד, איטום
מיידי, יציאה-גלויה אחת מפוקחת, אפס client-side, אפס לוגים). הסיכון האמיתי
נשאר בדיוק היכן שהביקורת סימנה: **המפתחות שכבר שרופים בריפואים האחרים, ה-PAT,
וה-daemons — וכולם בידי הבעלים בלבד.**

*כל ההוכחות כאן נמדדו 2026-09-08 מול ה-API וה-DB החיים של הריפו הזה.
הסיסמה ששימשה למבחן נמחקה יחד עם ה-state; אף סוד לא הודפס במסמך זה.*
