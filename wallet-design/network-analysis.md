## 2. ניתוח הרשת — תחת הנחת העבודה (⚠️ ידע ציבורי, לא קוד מהסביבה)

> כל הסעיף מבוסס תיעוד ציבורי של Steem/Hive. אין לראות בו ניתוח של קוד שנמצא. יעודכן לפי התבנית ב-`engineering/.../03_code_analysis/analysis-template.md` ברגע שקוד יתקבל.

### 2.1 ארכיטקטורה טכנית
- L1 עצמאי; צומת `steemd`/`hived` (C++, משפחת Graphene); בלוקים כל ~3 שניות; state חשבונאי מלא בצומת.
- פעולות (operations) מובנות-מראש (custom ops), לא EVM.
- שכבות: consensus (witnesses) → chain state → RPC plugins (condenser/api) → אפליקציות.

### 2.2 מנגנון קונצנזוס
- **DPoS**: 21 witnesses נבחרי הצבעה (stake-weighted), בלוקים בתורנות; חוקי hardfork גרסאיים.
- היררכיית מפתחות נייטיב לחשבון: **owner / active / posting / memo** — עם ספי חתימה (multi-sig authorities) — נדיר וייחודי לעומת רשתות EVM.

### 2.3 יכולות חוזים חכמים
- **אין EVM.** הרחבות באמצעות custom operations בצד הרשת או שכבות L2/צד-שרת. מגביל דאפים כלליים — אך מפשט ארנק (סט פעולות סגור ומנותח).

### 2.4 מבנה טוקן/כלכלה
- שלושה נכסים: נזיל (STEEM/HIVE), מטבע מוצמד-למחצה (SBD/HBD), ומופקד-מונע (SP/HP — vested).
- **Resource Credits (RC)**: מיטריקת משאב לפי stake שמאפשרת עסקאות ללא עמלות — עד שדלדול ה-RC.
- תגמולי תוכן (פיזור לאורך זמן), proposal system (מימון קהילתי), הצבעות witness.

### 2.5 APIs זמינים
- JSON-RPC על צומת (`condenser_api`, `block_api`, `account_history_api`, `database_api`), websockets להרשמות; ספריות לקוח JS (dhive/hive-js, steem-js). **לא אומת מול endpoint חי בסביבה זו.**

### 2.6 נקודות חוזק ייחודיות (מנוצלות בהמשך לרעיונות)
1. היררכיית מפתחות עם הרשאות גרנולריות (owner/active/posting/memo) — בסיס מושלם לארנק עם "מצבי פעולה".
2. עסקאות ללא עמלות ישירות (RC) — חוויית onboarding זולה.
3. פעולות חברתיות-native (פרסום/הצבעה/תגובה) — ארנק יכול להיות גם זהות חברתית.
4. memo key — ערוץ הצפנה נייטיב בין חשבונות.
5. RC delegation — "עזור לחבר לשלם דלק" נייטיב.
6. ממשל נייטיב (witnesses+proposals) בתוך הפרוטוקול.

### 2.7 הזדמנויות לחדשנות (סיכום — מפורט במסמך הבא)
הערך הגדול ביותר לארנק טמון בדברים שארנקים סטנדרטיים לא יכולים: מצבי-הרשאה, אפס-עמלות, זהות חברתית, הצפנת memo, וממשל מובנה — כולם נייטיב לרשת זו.

## 3. סיכום מנהלים של הניתוח

1. **עובדה:** אין רשת בסביבה; כל עבודת ארנק חייבת החלטת יעד רשת מפורשת לפני קוד ראשון.
2. **הנחה עובדת:** משפחת Steem — רשת עם מאפיינים שמאפשרים סוגי-ארנק שלא קיימים ב-EVM (מפורט ב-`breakthrough-ideas.md`).
3. **עיצוב בטוח גם תחת אי-ודאות:** הארכיטקטורה (מסמך הבא) תהיה **network-agnostic core + chain adapter** — ההשקעה בליבה לא הולכת לאיבוד גם אם ההנחה תתבדק.
4. **לא נעשה:** פיתוח מול הנחה ללא אישור RPC/chain-id; אין להקים "רשת משלנו" מ-fork ללא קהילה.
