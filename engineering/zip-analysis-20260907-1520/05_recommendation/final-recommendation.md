## 1. איזו מערכת בעלת הערך הרב ביותר להקמה על הרשת?

**שכבת נתונים — אינדקסר + API** (Indexer & API layer), עם ארנק self-custody כשלב שני.

דירוג מקדים של המועמדים (משוקלל 1–10; משקלים: ערך 0.25, אבטחה 0.20, היתכנות 0.20, שימוש ברור 0.15, יתרון תחרותי 0.10, סיכון-נמוך 0.10):

| מועמד | ציון משוקלל | שים לב |
|---|---|---|
| **אינדקסר + API** | **8.7** | קריאה-בלבד; אין סיכון כספים ישיר |
| ארנק self-custody | 8.3 | דורש ביקורת לפני חשיפה |
| כלי מסחר/דשבורד | 7.3 | תלוי באינדקסר |
| ולידטור/צומת תפעולי | 5.9 | תשתית, לא מוצר |

*(הציונים מקדימים ומותנים בהנחה; יעודכנו לפי התבנית ב-`03_code_analysis/analysis-template.md` עם קוד בפועל.)*

## 2. למה דווקא היא?

1. **ערך מיידי מדיד** — כל מפתח/משתמש על רשת זקוק לגישת נתונים מהירה ואמינה; השכבה הזו היא תנאי-סף לכל מוצר אחר.
2. **היתכנות גבוהה** — טכנולוגיות מוכרות (node RPC → Postgres → API cache); אין קוד consensus-critical.
3. **סיכון נמוך** — קריאה-בלבד בברירת מחדל; אין החזקת כספים; ניתן להשבית/לשחזר בלי השלכות כספיות.
4. **עלות טעות נמוכה** — טעות באינדקסר מתוקנת; טעות בקונצנזוס או בגשר עולה כסף אמיתי.
5. **מסלול הצמחה** — האינדקסר הוא הבסיס לכלי מסחר ולדאפים; הוא הצעד הראשון הנכון בכל המסלולים.

## 3. מה השימוש המעשי שלה?

- חיפוש יתרות, היסטוריית טרנזקציות, פעילות חשבונות — בשאילתות מילישניות במקום קריאות RPC כבדות.
- פידים למוצרים עוקבים (אקספלורר, דשבורד מסחר, התראות).
- API ציבורי יציב למפתחים צד-ג' במקום תלות בצמתים ציבוריים לא-מובטחים.

## 4. מה הערך שהיא נותנת?

- **למפתחים:** זמן-אינטגרציה קצר; יציבות; SLA מוגדר.
- **למשתמשי-קצה:** נתונים מהימנים בזמן אמת דרך מוצרים שנבנים מעליה.
- **לארגון:** נכס תשתית רב-פעמי; יתרון מול מתחרים שנשענים על API ציבורי.

## 5. למי היא מיועדת?

- מפתחי דאפים וכלי מסחר על הרשת הקיימת.
- צוותי ניתוח/ביקורת שזקוקים לנתונים היסטוריים עקביים.
- הארגון עצמו — כבסיס למוצרים הבאים במפת-הדרך.

## 6. איך היא מייצרת תועלת?

זרימה: `צומת RPC → מאזיני בלוקים → נרמול → Postgres (אינדוקס) → API (REST/GraphQL, cache) → מוצרים`.
תועלת נוצרת מהמרת גישה יקרה ואיטית לצומת לגישה זולה, מהירה וניתנת-לשיתוף.

## 7. איך נראית הוולידציה והאבטחה שלה?

- **אימות נתונים:** הצלבת hash בלוקים מול שני מקורות עצמאיים; בדיקות reorg; התאמת יתרות snapshot.
- **אבטחה:** קריאה-בלבד; rate limiting; אין מפתחות חמים בשלב 1; ארנק (שלב 2) עם חתימה מקומית בלבד + ביקורת חיצונית לפני פרסום.
- **תפעול:** ניטור lag, גיבויים, תוכנית incident response. **ללא הבטחות תשואה מכל סוג.**

## 8. האם היא מתאימה לרשת קיימת או לרשת עצמאית?

**לרשת קיימת ותוססת.** אינדקסר על רשת חדשה שהוקמה מ-fork של steem main יורש את כל בעיות הרשת (ביטחון, נזילות, קהילה) — בלי לפתור אף אחת מהן. הערך מופק מעל רשת שיש בה פעילות אמיתית.

## 9. מה היתרון שלה על פני האחרות?

| מול | יתרון |
|---|---|
| רשת חדשה (fork) | זמן-שוק קצר פי כמה; סיכון consensus אפס; אין צורך בגיוס ולידטורים |
| גשר | אין החזקת כספים; משטח התקפה קטן דרמטית |
| דאפ/כלי מסחר | תשתית לכל המוצרים במקום מוצר בודד |
| ולידטור | יצירת ערך לצדדים שלישיים, לא רק הכנסה תפעולית פרטית |

## 10. מה החולשות שלה?

- תלות מלאה בבריאות הרשת שמעליה היא בנויה (אם הרשת נוטה — השכבה נופלת איתה).
- ערך תחרותי נמוך יחסית אם קיים אינדקסר ציבורי טוב (יש באקוסיסטם Steem/Hive כלים קיימים).
- עלות תפעול מתמשכת (צומת + DB) ללא מודל הכנסה מובנה.
- חלון זמן: אם "steem main" הוא משהו אחר לגמרי — כל סעיף זה ישתנה.

## 11. מה צריך כדי להקים אותה?

| דרישה | פירוט |
|---|---|
| צומת | node מסונכרן של הרשת (read-only), 2 אזורי זמינות |
| DB | Postgres 16 + סכימת אינדוקס מנורמלת |
| שכבת API | Node/TypeScript (תואם לסטאק הפרויקט הקיים) עם cache בזיכרון |
| תשתית | Docker, CI/CD, ניטור (metrics+logs+alerts), גיבויים יומיים |
| אבטחה | rate limiting, WAF בסיסי, סודות ב-secret store (לא ב-.env גלוי) |
| כוח אדם | 1–2 מפתחי backend, 0.5 DevOps |
| זמן משוער | MVP אינדקסר+API: 4–6 שבועות; ארנק מבוקר: +6–8 שבועות |

## 12. מה תוכנית העבודה הראשונית?

מפורטת במלואה ב-[`../06_deployment_plan/deployment-roadmap.md`](../06_deployment_plan/deployment-roadmap.md). בקצרה: סינכרון צומת → אינדקסר MVP → API + cache → ולידציה מול מקור עצמאי → פיילוט סגור → (שלב ב') ארנק → ביקורת → ייצור.

## חלופות עם נימוקים

1. **ארנק self-custody (8.3)** — חלופה ראשונה אם קהל-היעד הוא משתמשי-קצה; מומלץ כשלב שני בכל מקרה, לאחר ביקורת אבטחה.
2. **כלי מסחר/דשבורד (7.3)** — אם קיים כבר אינדקסר ציבורי טוב לרשת; נבנה מעליו ולא מתחרה בו.
3. **לא נבחר: רשת חדשה מ-fork (3.5)** — עלות אבטחה/קהילה/רגולציה חורגת מהערך בשלב זה; אין עדות לקהילת ולידטורים שתתמוך ברשת חדשה.
