| שלב | מה | תוצר מאומת | משך משוער | תלות |
|---|---|---|---|---|
| 0 | קבלת וניתוח הקלט (ZIP/`steem main`) | ניתוח מבוסס ממצאים; עדכון ההמלצה | — | חסר כרגע |

## 2. תשתיות נדרשות

| רכיב | מפרט מינימלי | הערות |
|---|---|---|
| צומת רשת | 8 vCPU / 32GB RAM / 1TB NVMe | read-only; שני עותקים באזורים נפרדים |
| DB | Postgres 16, 4 vCPU / 16GB / 500GB NVMe | גיבוי PITR |
| API | 2 vCPU / 4GB × 2 מופעים | מאחורי load balancer |
| ניטור | Prometheus + Grafana / מקבילה | ראו סעיף 7 |
| CI/CD | GitHub Actions (או מקביל) | build → test → stage → prod; אין פריסה ידנית לייצור |

## 3. סביבת פיתוח

- ענף `main` מוגן; feature branches + PR עם בדיקות חובה.
- סביבת מקומית: docker-compose (postgres + node stub/mock).
- קוד ב-TypeScript/Node — תואם לסטאק הקיים בפרויקט; אין קוד consensus-critical.
- סודות: `.env` מקומי בלבד, לעולם לא בקוד; בייצור — secret store. (לקח מה-task: טוקן שהועלה ב-upload נחסם ע"י המערכת; ✏️ עודכן 2026-09-07: הטוקן התקין שהועלה בהמשך אינו נכנס ל-git כלל.)

## 4. סביבת בדיקות

- **testnet של הרשת** כקלט ראשי לכל בדיקות הארנק — אסור לגעת ב-mainnet בשלב בדיקות.
- בדיקות אינדוקס: שחזור מלא מ-block 0 מול רשת, התאמת יתרות מול snapshot עצמאי, בדיקות reorg.
- בדיקות API: חוזים (contract tests), קצה-קצה, עומס בסיסי.
- בדיקות ארנק: יצירת מפתחות/חתימה מקומית בלבד; fuzzing לחתימה; אימות שאין יציאת רשת של חומר מפתח.

## 5. סביבת ייצור

- פריסה immutable (תמונות Docker חתומות גרסה).
- 2 אזורי זמינות; failover ל-DB מתוסרגל מראש ומתורגל.
- הרשאות מינימליות (least privilege) לכל רכיב; אין SSH ישיר (access via bastion/SSO).

## 6. גיבויים

| פריט | מדיניות |
|---|---|
| DB | גיבוי מלא יומי + WAL ארכיון רציף (PITR); שימור 30 יום |
| קונפיגורציה | IaC בגיט; אין קונפיג ידני בייצור |
| ארנק | **אין אחזקת מפתחות בצד שרת** — מפתחות משתמש במכשיר המשתמש בלבד |
| בדיקות שחזור | תרגיל שחזור רבעוני מתועד |

## 7. ניטור

| מדד | סף התראה |
|---|---|
| אינדוקס lag (בלוקים) | > 10 בלוקים ל-5 דקות |
| סטיית יתרות מול מקור שני | כל סטייה ≠ 0 |
| API p95 latency | > 300ms ל-10 דקות |
| זמינות API | < 99.5% חודשי |
| שגיאות 5xx | > 1% ל-5 דקות |

## 8. אבטחה

- מודל איומים מתועד לפני שלב ייצור.
- קריאה-בלבד כברירת מחדל לכל רכיבי הנתונים.
- rate limiting + אימות API key לכתיבות (אין כתיבות ציבוריות בשלב 1).
- סריקת תלויות אוטומטית ב-CI (SCA), סריקת סודות ב-commit (כדי למנוע חזרה על תקרית הטוקן; ✏️ עודכן 2026-09-07: בוצע בפועל — `.env` ו-`upload/Roshcaregt.txt` הוסרו מהיסטוריית ה-git לפני ה-push הראשון).
- ארנק: חתימה מקומית בלבד, אישור כפול לשידור, ביקורת חיצונית חוסמת לפני חשיפה.

## 9. ולידציה

1. **נתונים:** התאמה 1:1 מול רשת על מדגם בלוקים אקראי + כל הטרנזקציות של 30 יום אחרונים.
2. **API:** חוזים נבדקים אוטומטית; תיעוד OpenAPI מסונכרן.
3. **ארנק (ב'):** סט testnet מקיף + סימולציית תרחישי תקיפה.
4. **תפעול:** תרגיל failover + תרגיל שחזור גיבוי לפני ייצור.

## 10. מדדי הצלחה

| מדד | יעד |
|---|---|
| דיוק יתרות מול רשת | 100% |
| אינדוקס lag | < 3 בלוקים ממוצע |
| זמינות API חודשית | ≥ 99.5% |
| p95 API latency | ≤ 100ms |
| אימוץ פיילוט | ≥ 10 מפתחים פעילים ב-30 יום |
| תקריות אבטחה חמורות | 0 |
